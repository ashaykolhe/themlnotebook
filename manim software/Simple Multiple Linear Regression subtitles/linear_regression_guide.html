01

What is Linear Regression?

Real-World Analogy First

You're a real estate agent. You notice bigger houses cost more. You collect data on 100 houses (size in sq ft, sale price), plot them, and draw the one straight line that best captures the trend. When a client asks "how much is a 2,000 sq ft house?", you look up 2,000 on the x-axis, trace to the line, read the price. That's linear regression.

Figure 1.1 — The regression line minimises the sum of squared vertical distances (residuals) from each data point.

What / How / Why / When / Where

What

A supervised learning algorithm that models the relationship between input features (X) and a continuous numerical target (y) as a linear function, then uses that function to make predictions on unseen data.

How

It finds the line (or hyperplane) that minimises the sum of squared differences between actual y values and predicted ŷ values — Ordinary Least Squares (OLS). It does this either analytically via the Normal Equation, or iteratively via gradient descent.

Why

Interpretable, extremely fast, has a proven closed-form solution, and is the canonical baseline model for any regression problem. If a simpler model can achieve acceptable performance, it should be preferred over complex ones.

When
  • Target is a continuous number (price, salary, temperature, demand)
  • The relationship between features and target is approximately linear
  • You need interpretability — stakeholders need to understand why predictions are made
  • As a mandatory baseline before trying ensemble/deep learning models
  • Small-to-medium datasets (thousands to low millions of rows)
Where (Industry Applications)
  • Finance: predicting stock returns, credit scoring, risk models
  • Real estate: property valuation (Zillow's Zestimate is partly linear)
  • Healthcare: predicting blood pressure, hospital length of stay, drug dosage
  • Marketing: sales forecasting from ad spend (media mix models)
  • Economics: GDP forecasting, demand elasticity
  • HR: salary benchmarking

Overall Pros & Cons — Linear Regression

✅ Pros

  • Highly interpretable — coefficients directly express feature effects in real units
  • Blazing fast — closed-form solution; training is O(np²)
  • No hyperparameters (base OLS) — no tuning needed out of the box
  • Theoretically optimal — BLUE (Best Linear Unbiased Estimator) per Gauss-Markov when assumptions hold
  • Extrapolates — can predict beyond the training range (though risky)
  • Statistical inference — p-values and confidence intervals via statsmodels
  • Great baseline — if it performs well, you don't need a complex model
  • Memory efficient — only stores p coefficients, not the training data

❌ Cons

  • Assumes linearity — fundamentally wrong for non-linear relationships
  • Sensitive to outliers — squared loss amplifies extreme errors enormously
  • Multicollinearity — correlated features produce unstable, uninterpretable coefficients
  • No automatic interactions — unlike tree models, won't learn feature interactions on its own
  • Struggles when p > n — more features than samples → Normal Eq fails
  • Scale sensitive — coefficients are not comparable across differently-scaled features
  • Strict assumptions — violated assumptions undermine inference (p-values become untrustworthy)
  • Not robust — single influential point can shift the entire line

The Mathematical Model

The Equation

Any straight line is y = mx + b. In ML notation:

ŷ = β₀ + β₁x₁ + β₂x₂ + ... + βₙxₙ
SymbolNameMeaning
ŷy-hat (predicted)Model's output. Not the true y — it's our best guess.
β₀Intercept / biasValue of ŷ when all features = 0. Where the line crosses the y-axis.
β₁…βₙCoefficients / weights / slopesHow much ŷ changes per 1-unit increase in that feature, all else constant.
x₁…xₙFeatures / predictors / independent varsThe inputs to the model.

Matrix (Vector) Form

ŷ = Xβ

X is the design matrix (n × p+1) — each row is one observation, the first column is all 1s (for β₀). β is a column vector (p+1 × 1). This compact form is what the computer actually computes.

The True Model — Error Term

y = β₀ + β₁x₁ + ... + βₙxₙ + ε
ε (epsilon) — The Error Term

What: The difference between the true y and the deterministic part of the model. It captures everything the model can't explain — noise, measurement error, missing variables.

Assumption: ε ~ N(0, σ²) — normally distributed with mean 0 and constant variance. This is not assumed about the raw data, only the errors.

Why it matters: The shape of ε's distribution determines whether OLS is the best estimator and whether our p-values are valid.

Interpreting Coefficients

Example: β₁ = 150 in a house price model

"For every additional square foot, the predicted price increases by $150, holding all other features constant."

The phrase "holding all other features constant" is critical — in multiple regression, each coefficient is a partial effect. It isolates the effect of one feature while the others stay fixed.

⚠️ Coefficients are Not Feature Importance if Features are Unscaled

A coefficient of 0.01 for income (in dollars) vs 2.5 for rooms doesn't mean rooms matter 250× more. Income is measured in large units. Always standardise features before comparing coefficients.

🎙 Interview: What's the difference between y and ŷ?
y is the actual observed value in your dataset. ŷ is the model's prediction. The difference y − ŷ is the residual. The model optimises β to make residuals as small as possible. The error term ε in the true model is the population-level equivalent of the sample residual.
03

Ordinary Least Squares (OLS)

The Cost Function

OLS finds β by minimising the Mean Squared Error — the average squared difference between actual and predicted values:

MSE(β) = (1/n) Σᵢ (yᵢ − ŷᵢ)² = (1/n) ||y − Xβ||²
Why square the errors — not just sum them?
  • Raw errors (y − ŷ) can be positive or negative. A model wildly off but symmetric would show zero total error — meaningless.
  • Squaring makes all errors positive, so they can't cancel.
  • Squaring penalises large errors more than small ones — good behaviour for most tasks.
  • The squared function is differentiable everywhere — critical for calculus-based optimisation.

Figure 3.1 — MSE is convex (bowl-shaped). Gradient descent always reaches the global minimum. No local minima exist for linear regression.

The Normal Equation — Closed-Form Solution

By setting the derivative of MSE with respect to β to zero and solving, we get an exact analytical answer:

β = (XᵀX)⁻¹ Xᵀy

Derivation (Step-by-Step)

  1. Write cost: J = (1/n)(y − Xβ)ᵀ(y − Xβ)
  2. Expand: J = (1/n)(yᵀy − 2βᵀXᵀy + βᵀXᵀXβ)
  3. Differentiate w.r.t. β: ∂J/∂β = (1/n)(−2Xᵀy + 2XᵀXβ)
  4. Set to zero: −2Xᵀy + 2XᵀXβ = 0
  5. Rearrange: XᵀXβ = Xᵀy (the "normal equations")
  6. Solve: β = (XᵀX)⁻¹Xᵀy ✓

Pros & Cons — Normal Equation / OLS

✅ Pros

  • Exact solution in one shot — no iterations, no learning rate to tune
  • Deterministic — same answer every run, no randomness
  • Works well for small datasets (n large, p small)
  • Gives optimal β directly — no convergence criterion needed

❌ Cons

  • O(p³) — matrix inversion scales cubically with features. 10k features is very slow.
  • Fails if XᵀX is singular — happens with perfect multicollinearity or p > n
  • Memory intensive — must hold XᵀX (p×p matrix) in RAM
  • Not suitable for online/streaming learning (gradient descent can update incrementally)
⚠️ sklearn uses SVD, not direct matrix inversion

sklearn's LinearRegression uses Singular Value Decomposition (SVD) via numpy.linalg.lstsq, not the explicit (XᵀX)⁻¹ formula. Direct inversion is numerically unstable — small floating-point errors can explode. SVD computes the pseudoinverse and handles near-singular matrices gracefully. Result is mathematically equivalent but numerically safe.

🎙 Interview: What is the Ridge closed-form solution, and why does it always work even with multicollinearity?
Ridge modifies the Normal Equation: β = (XᵀX + λI)⁻¹Xᵀy. Adding λI to the diagonal ensures the matrix is always invertible (positive definite) even when XᵀX would be singular. This is both the mathematical and geometric explanation for why Ridge handles multicollinearity elegantly.
04

The LINE-MO Assumptions

Linear regression has 6 assumptions for the model to be statistically valid. Use the mnemonic LINE-MO.

L — Linearity

The mean of y is a linear function of X.

I — Independence

Observations are independent — residuals are not correlated across data points.

N — Normality of Residuals

The errors ε follow a normal distribution. Needed for valid p-values & CIs.

E — Equal Variance (Homoscedasticity)

Residual variance is constant across all levels of X.

M — No Multicollinearity

Predictors are not highly correlated with each other.

O — No Outliers / Leverage

No extreme points that disproportionately influence the fitted line.

L — Linearity

What: E[y|X] = Xβ. The true relationship between X and y is linear.

How to detect: Residuals vs. Fitted plot — a curved or systematic pattern means linearity is violated.

Figure 4.1 — Residuals vs. Fitted plots. Left: linearity holds. Right: U-shape signals a non-linear relationship.

Remedy: Add polynomial features (x², x³), apply log/sqrt transform to X or y, or use a non-linear model.

✅ When it holds

  • OLS is theoretically optimal (BLUE)
  • Coefficients are easily interpretable
  • Extrapolation is reasonable

❌ When it's violated

  • Predictions are systematically biased
  • Residuals show patterns — visible in diagnostics
  • Must add polynomial features or switch models

E — Equal Variance (Homoscedasticity)

What: Var(ε|X) = σ² — the variance of residuals is constant across all X values.

How to detect: Residuals vs. Fitted plot (fan/funnel shape). Scale-Location plot. Breusch-Pagan test.

Figure 4.2 — Left: equal spread of residuals (good). Right: spread increases with fitted value (heteroscedastic).

Consequences if violated: OLS estimates remain unbiased but are no longer efficient. Standard errors are wrong → p-values and confidence intervals are unreliable.

Remedies: Log-transform y (most common), use Weighted Least Squares (WLS), use heteroscedasticity-consistent (HC3) standard errors.

✅ When it holds

  • OLS is efficient (BLUE)
  • Standard errors, p-values, CIs are valid
  • Residual plots are clean

❌ When violated (heteroscedasticity)

  • Standard errors are biased → bad p-values
  • Confidence intervals are too narrow or too wide
  • OLS is no longer the most efficient estimator

M — No Multicollinearity

What: Predictor variables should not be highly correlated with each other.

Analogy: Imagine predicting salary from both height (cm) and height (inches). They're the same thing — the model has infinite ways to split the weight between them, producing wildly unstable coefficients.

How to detect: Variance Inflation Factor (VIF) — VIF > 5: warning; VIF > 10: severe.

VIF(βⱼ) = 1 / (1 − R²ⱼ) where R²ⱼ = R² from regressing xⱼ on all other features

Remedies: Remove one of the correlated features, combine them (e.g., average), use PCA, or use Ridge regression (which handles multicollinearity by design).

✅ When absent (low VIF)

  • Coefficients are stable and interpretable
  • Standard errors are small
  • Can meaningfully compare feature importance

❌ When present (high VIF)

  • Coefficient estimates are unstable — flip sign with small data changes
  • Standard errors inflate → wide confidence intervals
  • Coefficients become uninterpretable individually
  • Normal Equation may become numerically singular

I — Independence of Errors

What: The error for observation i tells you nothing about the error for observation j. Cov(εᵢ, εⱼ) = 0 for i ≠ j.

Common violation: Time-series data — yesterday's error predicts today's (autocorrelation). Also: grouped data (multiple readings from same patient).

How to detect: Durbin-Watson test (value ≈ 2 = no autocorrelation; near 0 = positive; near 4 = negative). ACF/PACF plots of residuals.

Remedy: Add lag features, use ARIMA/time-series models, use GLS (Generalized Least Squares), cluster-robust standard errors.

✅ When it holds

  • Standard errors are correctly estimated
  • No systematic patterns in residuals over time or groups

❌ When violated (autocorrelation)

  • Standard errors are underestimated → inflated t-stats and false significance
  • Predictions are poor for sequential/grouped data
  • Model is systematically wrong in structured ways

N — Normality of Residuals

What: The residuals (not y, not X) should be approximately normally distributed.

⚠️
Critical misconception: This assumption is about the residuals, NOT the raw data. Your input features can follow any distribution. This also matters mainly for inference (p-values, CIs) — not for prediction accuracy. With large samples (n > 30+), the Central Limit Theorem makes OLS robust to non-normality.

How to detect: Q-Q plot (points should fall on diagonal). Shapiro-Wilk test (small samples), Kolmogorov-Smirnov test (large).

Remedy: Log/sqrt transform y, remove outliers, use robust regression.

✅ When it holds

  • t-tests and F-tests on coefficients are exactly valid
  • Confidence intervals are correctly sized
  • Small-sample inference is reliable

❌ When violated

  • p-values and CIs may be inaccurate (especially for small n)
  • For large n: CLT saves you — predictions still fine
  • For small n: bootstrap confidence intervals as alternative

O — No Extreme Outliers / High-Leverage Points

Outlier: Unusual y value — far from the regression line (high residual).

High-leverage point: Unusual X value — far from the centroid of X-space. Can "pull" the regression line toward it.

Influential point: High leverage + high residual = changes coefficients dramatically when removed (measured by Cook's Distance).

Remedy: Investigate (data entry error? genuine extreme case?), remove if erroneous, transform, or use Huber/RANSAC regression.

✅ When outliers are absent

  • Coefficients represent the typical relationship
  • MSE is a faithful measure of model error

❌ When influential outliers are present

  • A single point can dominate the entire regression line
  • Coefficients may be completely distorted
  • RMSE is artificially inflated
🎙 Tricky Interview: "Does linear regression assume the data is normally distributed?"
No — very common misconception! Linear regression assumes the residuals (errors) are normally distributed, not the raw X or y data. Your input features can be skewed, uniform, or anything. Even the residual normality assumption is mainly needed for valid inference (p-values), not for predictions. For large enough samples, the CLT makes this assumption less critical.

MSE — Mean Squared Error

MSE = (1/n) Σᵢ (yᵢ − ŷᵢ)²

Intuition: Average of squared prediction errors. Squaring both makes all errors positive and heavily penalises large errors.

✅ Pros

  • Differentiable everywhere — mathematically clean for gradient-based optimisation
  • Penalises large errors more — good when big mistakes are very costly
  • Convex — unique global minimum

❌ Cons

  • Units are squared (e.g., dollars² for prices) — not directly interpretable
  • Very sensitive to outliers — one extreme error dominates the score
  • Two models with very different error distributions can have the same MSE

RMSE — Root Mean Squared Error

RMSE = √MSE = √[ (1/n) Σ (yᵢ − ŷᵢ)² ]

Intuition: Take the square root to get back to original units. RMSE = 25,000 on house prices → "on average, predictions are off by ~$25,000."

✅ Pros

  • Same units as y — directly interpretable
  • Still penalises large errors (from squared term)
  • Most widely used metric in regression competitions (Kaggle)

❌ Cons

  • Still sensitive to outliers (inherited from MSE)
  • Not scale-invariant — can't compare RMSE across different target scales

MAE — Mean Absolute Error

MAE = (1/n) Σ |yᵢ − ŷᵢ|

Intuition: Average of absolute errors. Treats all errors equally — a $1,000 error is 10× worse than a $100 error (not 100× as in MSE).

✅ Pros

  • Robust to outliers — extreme errors don't dominate
  • Same units as y — easy to explain to non-technical stakeholders
  • More interpretable average error than RMSE

❌ Cons

  • Not differentiable at 0 — subgradient needed; slightly harder to optimise
  • Treats all errors equally — may underweight serious large errors
  • Less mathematically clean than MSE for theoretical derivations

R² — Coefficient of Determination

R² = 1 − SS_res / SS_tot = 1 − Σ(yᵢ−ŷᵢ)² / Σ(yᵢ−ȳ)²

Figure 5.1 — R² = 1 − SS_res/SS_tot. Left: predicting ȳ (baseline). Right: model reduces errors dramatically.

R² ValueInterpretationContext
< 0Worse than predicting the mean!Model is broken or evaluated on wrong data
0.0No better than baseline (ȳ)Features explain nothing
0.3–0.5ModerateSocial science, economics
0.7–0.9GoodTypical ML regression task
0.95+ExcellentEngineering, physics
1.0Perfect — highly suspiciousLikely data leakage or degenerate setup

✅ Pros of R²

  • Scale-independent — 0–1 range comparable across datasets
  • Intuitive: "the model explains X% of the variance in y"
  • Widely understood — good for reporting to stakeholders

❌ Cons of R²

  • Always increases when you add features — even useless ones
  • Says nothing about assumption violations or coefficient correctness
  • Sensitive to scale — a high R² on log(y) doesn't directly translate to raw y
  • Can be negative on test sets if model is worse than the mean predictor

Adjusted R² — The Honest R²

Adj R² = 1 − (1 − R²) × (n − 1) / (n − p − 1)

Why it exists: R² mechanically increases when you add any feature (even random noise). Adjusted R² penalises for extra features — it only improves if the new feature genuinely helps beyond what random chance would give.

✅ Pros

  • Penalises model complexity — prevents feature inflation
  • Better for comparing models with different numbers of features
  • Decreases when useless features are added

❌ Cons

  • Still doesn't check assumption validity
  • Doesn't measure predictive accuracy the way CV does
  • Can still be gamed if you tune heavily on training data

MAPE — Mean Absolute Percentage Error

MAPE = (100/n) Σ |yᵢ − ŷᵢ| / |yᵢ|

Intuition: "On average, my predictions are off by X%." Immediately understandable by business stakeholders without knowing the units.

✅ Pros

  • Percentage-based — easily communicated to non-technical teams
  • Scale-independent — compare across different products/targets
  • Intuitive: MAPE = 5% is immediately meaningful

❌ Cons

  • Undefined when yᵢ = 0 (division by zero)
  • Asymmetric — over-predictions and under-predictions are penalised differently
  • Heavily penalises underestimates vs. overestimates when y is small
  • Not suitable for targets near zero
🎙 Tricky Interview: Can R² be negative? When?
Yes. R² = 1 − SS_res/SS_tot. If SS_res > SS_tot — i.e., the model's errors are larger than just predicting the mean — R² goes negative. This happens when: (1) evaluating on a test set after severe overfitting, (2) forcing fit_intercept=False on data that doesn't pass through the origin, or (3) a preprocessing/scaling mistake on the test set. R² < 0 is a red flag — the model is actively harmful compared to always predicting ȳ.
🎙 Interview: When would you choose MAE over RMSE?
Choose MAE when: (1) your target has genuine outliers that aren't data errors and you don't want them to dominate your metric (e.g., predicting delivery time where occasional extreme delays are real but rare), (2) your business cares equally about all errors regardless of size, (3) you need to explain model performance to non-technical stakeholders in simple terms. Choose RMSE when large errors are disproportionately more costly (e.g., structural engineering, financial risk).

Gradient Descent

Why Gradient Descent?

When the dataset has millions of rows or thousands of features, the Normal Equation's O(p³) matrix inversion becomes impractical. Gradient descent finds the minimum iteratively instead of analytically.

Analogy: You're blindfolded on a hilly landscape trying to find the valley. At each step you feel which direction is downhill (the gradient) and take one step in that direction. Repeat until you can't go further downhill.

β_new := β_old − α × ∂MSE/∂β
∂MSE/∂β = −(2/n) Xᵀ(y − Xβ)
  1. Initialise β (all zeros, or random small values)
  2. Compute predictions: ŷ = Xβ
  3. Compute residuals: e = y − ŷ
  4. Compute gradient: ∇ = −(2/n) Xᵀe
  5. Update coefficients: β ← β − α × ∇
  6. Repeat until ‖∇‖ < ε or max iterations reached

Figure 6.1 — Learning rate α is the most critical hyperparameter. Too high → overshoots. Too low → wastes time. Optimal → smooth exponential decay.

Pros & Cons — Gradient Descent for Linear Regression

✅ Pros

  • Scales to millions of samples and thousands of features
  • Can use mini-batches — memory efficient, no need to load all data at once
  • Foundation for deep learning — same algorithm used in neural nets
  • Can be extended to non-convex losses easily
  • Online learning capable — update model as new data arrives

❌ Cons

  • Requires choosing learning rate α — wrong choice = slow or divergence
  • Iterative — no single closed-form answer; needs convergence criterion
  • Sensitive to feature scaling — must standardise features first
  • Not needed for linear regression with small p — Normal Equation is faster and exact
  • May oscillate around minimum without a decaying LR schedule (SGD)
🎙 Interview: Does gradient descent always find the global minimum for linear regression?
Yes — because MSE for linear regression is strictly convex (a perfect bowl). There are no local minima, no saddle points to get stuck in. Any run of gradient descent with a suitable learning rate will reach the global minimum. This contrasts sharply with neural networks, which are non-convex. Ridge regression is also convex. Lasso has a non-differentiable point at zero but is still convex — coordinate descent handles it.

Regularization: Ridge, Lasso & ElasticNet

The Problem: Overfitting & Large Coefficients

When a model has many features, OLS can produce very large coefficients to fit training noise. This causes poor generalisation to new data (overfitting). Regularisation adds a penalty on coefficient size to the cost function, constraining how large they can get.

Figure 7.1 — The regularised model (green line, left) generalises. The overfit model (red curve, right) passes through every point but fails on unseen data.

Ridge Regression (L2 Regularisation)

Cost = MSE + λ Σⱼ βⱼ²

What it does: Adds the sum of squared coefficients as a penalty. Shrinks all coefficients toward zero but never exactly to zero.

Closed-form solution: β = (XᵀX + λI)⁻¹Xᵀy — always invertible, even with multicollinearity.

λ (called alpha in sklearn): λ=0 → plain OLS. λ→∞ → all β→0.

✅ Pros of Ridge

  • Handles multicollinearity — distributes weight across correlated features
  • Always has a unique, stable solution (XᵀX + λI always invertible)
  • Closed-form — still very fast to compute
  • Keeps all features — good when you believe all features matter
  • Lower variance than OLS when features are correlated

❌ Cons of Ridge

  • No feature selection — all coefficients stay non-zero (just smaller)
  • Coefficients are biased (introduces bias to reduce variance)
  • λ must be tuned via cross-validation
  • Less interpretable than OLS when λ is large (coefficients are shrunk)

Figure 7.2 — The ellipses are MSE contours. Ridge's circular boundary is smooth — the touching point is off the axis. Lasso's diamond has corners exactly on the axes — the MSE ellipse almost always first touches a corner, making that coefficient exactly 0.

Lasso Regression (L1 Regularisation)

Cost = MSE + λ Σⱼ |βⱼ|

What it does: Adds the sum of absolute values of coefficients as a penalty. Unlike Ridge, L1 can drive some coefficients to exactly zero — performing automatic feature selection.

✅ Pros of Lasso

  • Built-in feature selection — zero coefficients remove irrelevant features
  • Produces sparse models — easier to interpret when many features exist
  • Good when true model is sparse (only a few features truly matter)
  • Helps when you have thousands of features (genomics, text, etc.)

❌ Cons of Lasso

  • No closed form — iterative coordinate descent required
  • When features are correlated, Lasso arbitrarily picks one and zeros the others — unstable
  • Poor at handling groups of correlated predictors
  • λ must be tuned; too high → over-sparse (important features zeroed out)
  • Slower than Ridge for large datasets

ElasticNet (L1 + L2 Combined)

Cost = MSE + α × [ r × Σ|βⱼ| + (1−r)/2 × Σβⱼ² ]

Where alpha is the overall penalty strength and l1_ratio (r) controls the mix: 0 = pure Ridge, 1 = pure Lasso.

✅ Pros of ElasticNet

  • Best of both worlds — sparsity from L1 + stability from L2
  • Handles groups of correlated features better than Lasso alone (tends to keep or drop them together)
  • More robust than Lasso in high-dimensional settings
  • Flexible via l1_ratio tuning

❌ Cons of ElasticNet

  • Two hyperparameters to tune (alpha and l1_ratio) — more search space
  • No closed form — iterative, slower than Ridge
  • Interpretation slightly more complex
  • Often overkill — if you know the setting, pick Ridge or Lasso specifically

🎙 Tricky Interview: Why does L1 produce sparsity but L2 doesn't?
Geometric answer: L1's constraint region is a diamond with corners on the coordinate axes. The MSE ellipse almost always first touches the diamond at a corner (where one β = 0). L2's circular boundary has no corners — the ellipse touches it at a smooth point where all coordinates are non-zero.

Calculus answer: L2 penalty derivative = 2βⱼ → shrinks proportionally to current size → approaches zero but never reaches it. L1 penalty derivative = sign(βⱼ) → constant push toward zero regardless of current size → can reach exactly zero.

Residual Diagnostics

After fitting, always run these 4 diagnostic plots to validate assumptions.

Figure 8.1 — Run all 4 plots after every fit. Green = good. If you see problems, address the assumption violation before trusting the model.

Cook's Distance

What: Measures how much all fitted values would change if a single observation were removed. Combines leverage (unusual X) and residual (unusual y) into one influence score.

Dᵢ = (ŷ(−i) − ŷ)ᵀ(ŷ(−i) − ŷ) / (p × MSE)

Threshold: Cook's D > 4/n → investigate. Cook's D > 1 → very high influence.

✅ When Cook's D is low

  • No single point dominates the regression
  • Coefficients are representative of the full dataset
  • Robust and reliable estimates

❌ When Cook's D is high

  • A single point could be controlling the entire model
  • Removing it drastically changes predictions
  • Signals the model isn't capturing the general pattern
🎙 Interview: Difference between an outlier, a high-leverage point, and an influential observation?
Outlier: Unusual y value — far from the fitted line (high residual). Doesn't necessarily distort the line if it's at a typical x value.
High-leverage point: Unusual X value — far from the centre of the predictor space. Has the potential to pull the line but doesn't necessarily if its y is consistent with the trend.
Influential observation: High Cook's D = both unusual X AND unusual y. Removing it changes the fitted line significantly. This is the dangerous one.

Feature Engineering for Linear Regression

Linear regression only captures linear relationships by default. Feature engineering is how we extend its power to handle non-linearity, interactions, and different data types.

Interaction Terms

An interaction term is x₁ × x₂ — it allows the effect of one feature to depend on another. Example: "the effect of advertising spend depends on whether it's peak season."

ŷ = β₀ + β₁ × ad_spend + β₂ × is_peak + β₃ × (ad_spend × is_peak)

Here β₃ captures the extra boost advertising gets during peak season that neither term alone can express.

Pros: Captures complex conditional effects, keeps model linear in parameters. Cons: Combinatorial explosion with many features; hard to interpret with many interactions.

Encoding Categorical Features

Linear regression requires all features to be numeric. Categories must be encoded:

One-Hot EncodingCreates k−1 binary columns for k categoriesNominal categories (colour, city, type)Drop one column to avoid perfect multicollinearity (dummy variable trap)

⚠️ The Dummy Variable Trap

With k categories, one-hot encoding creates k binary columns. If you include all k, they sum to 1 — perfectly predictable from each other. This is perfect multicollinearity and makes XᵀX singular. Always drop one category (the reference category). sklearn's OneHotEncoder has drop='first' for this.

Feature Scaling

Linear regression coefficients are scale-dependent. Scaling is required for: (1) comparing feature importance via coefficients, (2) regularisation (Ridge/Lasso penalise all coefficients equally — unfair if scales differ), (3) gradient descent convergence speed.

🎙 Interview: Does OLS (plain LinearRegression) need feature scaling?
For predictions and R²: No — OLS produces correct predictions regardless of scale. The predictions ŷ = Xβ are scale-invariant because the coefficients adjust automatically. For interpreting coefficients: Yes — scaled coefficients let you compare feature importance. For regularised models (Ridge/Lasso): Mandatory — the penalty term treats all βⱼ equally, so unscaled features with large values dominate the penalty unfairly.

Overfitting, Underfitting & Bias-Variance Tradeoff

The Three Regimes

Figure 10.1 — Underfitting: too simple a model. Overfitting: too complex. Goal: the right complexity that generalises.

The Bias-Variance Tradeoff

Every model's error decomposes as:

E[(y − ŷ)²] = Bias² + Variance + Irreducible Noise
ComponentMeaningCaused byReduced by
Bias²Systematic error — model is consistently wrong in the same directionToo simple a model (underfitting), wrong assumptionsMore features, polynomial terms, more complex model
VarianceSensitivity error — model changes a lot with different training samplesToo complex a model (overfitting), too many featuresRegularisation, more data, simpler model
Irreducible NoiseInherent randomness in y that no model can explainMeasurement error, missing variables, true randomnessCannot be reduced — it's the floor

Figure 10.2 — As model complexity increases, bias decreases but variance rises. The sweet spot minimises total error — found via cross-validation.

How This Applies to Linear Regression Specifically

SituationBiasVarianceFix
Plain OLS, few features, true relationship is non-linearHighLowAdd polynomial features or interactions
OLS with many features, p ≈ nLowHighRegularise with Ridge or Lasso
Ridge with high λModerateLowReduce λ via cross-validation
Ridge with λ ≈ 0Very lowHigherIncrease λ
🎙 Interview: How does regularisation control the bias-variance tradeoff?
Regularisation (Ridge/Lasso) introduces a controlled amount of bias (it shrinks coefficients away from OLS estimates) in exchange for a reduction in variance (coefficients become more stable across different training samples). As λ increases: bias increases, variance decreases. As λ → 0: back to OLS (zero bias, maximum variance). The optimal λ balances these — found by minimising cross-validation error.

Cross-Validation & Pipelines

Why Not Just Train/Test Split?

A single train/test split gives one estimate of performance. Its variance is high — you might get lucky or unlucky with how the split falls. Cross-validation averages over many splits to give a more reliable estimate.

Figure 11.1 — In 5-fold CV, each fold takes a turn as the test set. Final score = average of 5 scores. Much more reliable than one split.

✅ Pros of Cross-Validation

  • More reliable performance estimate — averages out lucky/unlucky splits
  • Uses all data for both training and testing (efficient)
  • Detects overfitting — gap between train and CV score signals it
  • Required for tuning hyperparameters without test set leakage

❌ Cons of Cross-Validation

  • k× more expensive to compute — fits k models instead of 1
  • Shouldn't be used for time-series data (use TimeSeriesSplit instead — no data leakage from future)
  • For very large datasets, CV may be too slow — use a single large holdout

Pipelines — Preventing Data Leakage

⛔ What is Data Leakage?

Leakage occurs when information from the test set "leaks" into the training process, making your model appear better than it really is. The most common cause: fitting StandardScaler on the full dataset before splitting — the scaler "knows" the test set's mean and std. This inflates performance metrics.

Fix: Always use a Pipeline — it ensures scaling (and all other preprocessing) is fit only on training data and applied to test data using training statistics.

# ❌ WRONG — leaks test data into scaler
scaler = StandardScaler()
X_scaled = scaler.fit_transform(X)  # uses full dataset!
X_train, X_test = train_test_split(X_scaled)

# ✅ CORRECT — scaler only sees training data
pipeline = Pipeline([
    ('scaler', StandardScaler()),
    ('model',  LinearRegression())
])
pipeline.fit(X_train, y_train)   # scaler.fit() only on X_train
pipeline.predict(X_test)          # scaler.transform() applied to X_test

✅ Pros of Pipelines

  • Eliminates data leakage by design
  • One object to fit, transform, and predict — cleaner code
  • Works seamlessly with GridSearchCV / cross_val_score
  • Serialise the whole workflow with one joblib.dump()

❌ Cons of Pipelines

  • Slightly harder to debug individual steps
  • Parameter names need stepname__param prefix in GridSearch
  • Some advanced custom transforms require writing a custom sklearn transformer

Tricky Interview Questions & Full Model Answers

Q1. Can you use linear regression for classification?
Technically yes, but it's a bad idea. Predictions are unbounded (can exceed 1 or go below 0), so they can't be treated as probabilities. Also, MSE penalises far-away class labels more than nearby ones — wrong behaviour for classification. The correct tool is Logistic Regression, which is still linear in its parameters but passes through a sigmoid to bound outputs to [0,1]. That said, the Linear Probability Model (OLS on a 0/1 target) is used in econometrics where coefficient interpretability outweighs this limitation.
Q2. Does linear regression need feature scaling? Doesn't OLS automatically adjust?
For predictions and R²: OLS is scale-invariant — the predictions ŷ = Xβ are correct regardless of scale because β adjusts to compensate. For comparing coefficients: you must scale — a coefficient of 0.001 on income (dollars) vs. 5 on rooms doesn't mean rooms matter 5000× more. For regularisation (Ridge/Lasso): scaling is mandatory — the penalty treats all βⱼ equally, so a large-scale feature gets unjustly penalised. For gradient descent: scaling is critical — poorly scaled features create an elongated loss surface where gradient descent bounces and converges slowly.
Q3. What is the Gauss-Markov theorem, and why should an interviewer care?
Under the classical OLS assumptions (linearity, independence, homoscedasticity, no perfect multicollinearity — but NOT requiring normality), the OLS estimator is BLUE: Best Linear Unbiased Estimator. "Best" = lowest variance among all linear unbiased estimators. This is the theoretical justification for OLS being the default. It tells you: as long as assumptions hold, no other linear method can do better. When assumptions are violated, BLUE breaks down — which is why Ridge (biased but lower variance) can actually improve performance.
Q4. Why does Ridge work better than OLS with multicollinearity?
With multicollinearity, XᵀX has very small eigenvalues (near-singular), meaning small changes in y produce huge changes in β = (XᵀX)⁻¹Xᵀy. Ridge adds λI to the diagonal: β_ridge = (XᵀX + λI)⁻¹Xᵀy. This raises all eigenvalues by λ, making the matrix well-conditioned. The result is that β_ridge is biased (coefficients are shrunk) but has dramatically lower variance — so it generalises better to test data despite being "wrong" on training data.
Q5. Walk me through what happens when you have more features than observations (p > n).
Three things fail: (1) XᵀX is singular — rank(X) ≤ n, so XᵀX (p×p) cannot be inverted. Infinitely many β vectors give zero training error. (2) OLS overfits perfectly — with p > n degrees of freedom, you can fit any training data exactly. Training R² = 1, test R² = garbage. (3) Coefficients are meaningless — you can't interpret which features matter. Fix: Lasso (selects a sparse subset), Ridge (shrinks and stabilises), or PCA (reduces to n dimensions first). Lasso is most natural here because it effectively reduces the problem to a smaller feature set.
Q6. A model has high R² on training data but low R² on test data. What are all possible causes and fixes?
Causes: (1) Too many features relative to data (overfitting). (2) Features were engineered on the full dataset before splitting (data leakage). (3) StandardScaler fit on full dataset (leakage). (4) Hyperparameters tuned on test set. (5) Test set is genuinely different in distribution (data drift).

Fixes: (1) → Regularise with Ridge/Lasso, reduce features. (2) & (3) → Use Pipeline — ensures all preprocessing is fit only on train. (4) → Use cross-validation, never touch test set during tuning. (5) → Collect more representative data, use robust features.
Q7. What is heteroscedasticity, how would you detect it, and what would you do about it?
What: The variance of residuals changes with fitted values (fan shape in residual plots). Example: predicting house prices — small houses have tight errors but large luxury homes have huge variability.

Detect: (1) Residuals vs. Fitted plot — look for fan/funnel shape. (2) Scale-Location plot — should be flat. (3) Breusch-Pagan test (statsmodels).

Fix: (1) Log-transform y — most effective when variance grows proportionally to y. (2) Weighted Least Squares — upweight low-variance observations. (3) Use HC3 robust standard errors (statsmodels.OLS with cov_type='HC3') — fixes p-values without changing β. (4) Box-Cox transformation — systematic approach to find the best power transform.
Q8. How would you handle outliers in linear regression?
First, diagnose: Cook's Distance plot, studentised residuals, leverage hat matrix.
Then decide:
(1) Data error → fix or remove the point.
(2) Genuine extreme case that should be modelled → use Huber Regression (sklearn's HuberRegressor) — behaves like OLS for small residuals, like MAE for large ones.
(3) Many scattered outliers → RANSAC (fits on random inlier subsets) or Theil-Sen estimator (median-based slopes).
(4) Transform y → log(y) often makes extreme values less extreme.
Never blindly remove outliers — always understand why they exist.
Q9. You add 50 random features to your model and R² improves. Does that mean the model is better?
No. R² always weakly increases when you add features — even random noise will marginally fit training fluctuations. This is the fundamental problem with R² for model selection. The right measures are: (1) Adjusted R² — penalises for adding features; if it decreases, the new features aren't worth it. (2) Cross-validation RMSE — truly out-of-sample performance; adding random features will degrade CV RMSE (overfitting). (3) AIC / BIC — information criteria that penalise complexity. The correct question is always: "Does adding this feature improve cross-validated performance?"
Q10. What are the pros and cons of using MAE vs. RMSE as your training loss?
RMSE (MSE) as loss: Differentiable everywhere → closed-form solution possible. Gradient is smooth. Heavily penalises large errors → useful when big mistakes are costly. But amplifies outliers.

MAE as loss: Robust to outliers — a single extreme point doesn't dominate. But non-differentiable at 0 (need subgradient). No closed-form OLS solution — must use iterative methods. In practice: train with RMSE (OLS is optimal), then report MAE as your evaluation metric if you want outlier-robust reporting. Or use HuberRegressor which transitions between the two.
Q11. Explain data leakage in the context of a preprocessing pipeline.
Leakage means your model secretly learns from the test set during training, producing unrealistically good metrics. The most common form: fitting a StandardScaler on the entire dataset before train/test split. The scaler computes mean and std from test set rows, so the "test set" is no longer truly unseen — its statistics were used in preprocessing. Fix: always use a Pipeline. Pipeline.fit(X_train) fits the scaler on train only. Pipeline.predict(X_test) applies those train-derived statistics to test. Other leakage forms: computing target encoding without CV, feature selection using all data before splitting, imputing missing values using the full dataset's mean.
Q12. Walk me through building a production-ready linear regression model from scratch.
1. EDA: distributions, correlations (heatmap), missing values, outlier detection, target distribution shape.
2. Preprocessing: impute missing values (median/mean), encode categoricals (one-hot, drop first), log-transform skewed features/target, StandardScaler in pipeline.
3. Baseline: fit plain OLS, get train + 5-fold CV metrics (R², RMSE, MAE).
4. Diagnostics: residuals vs. fitted, Q-Q plot, Scale-Location, Cook's Distance, VIF for multicollinearity.
5. Address violations: transform features/target for non-linearity or heteroscedasticity; remove/combine collinear features.
6. Regularise: try Ridge (RidgeCV), Lasso (LassoCV), ElasticNet. Compare CV performance.
7. Interpret: report standardised coefficients, feature importance ranking, confidence intervals (statsmodels).
8. Final evaluation: run on held-out test set exactly once. Report RMSE, MAE, R².
9. Production: save full Pipeline with joblib.dump(). Monitor for data drift (input distribution) and concept drift (relationship changes) post-deployment.
🏁 Master Summary — Everything You Need to Remember
  • What it is: Fits ŷ = Xβ by minimising MSE = (1/n)Σ(y−ŷ)² via OLS or gradient descent
  • Closed form: β = (XᵀX)⁻¹Xᵀy — sklearn uses SVD for numerical stability
  • Assumptions (LINE-MO): Linearity, Independence, Normality of residuals, Equal Variance, No Multicollinearity, No Outliers — each with detection test and remedy
  • Metrics: RMSE (interpretable, outlier-sensitive), MAE (robust, interpretable), R² (variance explained, always tune Adjusted R² for model selection), MAPE (percentage, avoid y≈0)
  • Regularisation: Ridge (L2, no zeros, handles multicollinearity), Lasso (L1, exact zeros, feature selection), ElasticNet (both)
  • Bias-Variance: regularisation increases bias but decreases variance — optimal λ found via cross-validation
  • Pipeline is mandatory: prevents data leakage, ensures preprocessing uses only training data
  • Always run 4 diagnostic plots after fitting: Residuals vs. Fitted, Q-Q, Scale-Location, Cook's Distance
  • Pros: interpretable, fast, BLUE under assumptions, no hyperparameters (OLS), great baseline
  • Cons: linearity assumption, outlier sensitivity, can't handle interactions automatically, strict assumptions for valid inference
